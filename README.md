# distributed-memory-optimization-suite

Deterministic memory optimization for distributed agent fleets: recency-weighted retention scoring, similarity-based compaction, budget eviction, and multi-node coordination — with zero runtime dependencies.

## The problem

A long-lived agent that records everything it observes hits a wall: its context budget fills with stale episodes, near-duplicate notes (the same incident reported twice with slightly different wording), and low-value digests nobody will ever retrieve. In a fleet the problem compounds — every node overflows independently, nobody can say which memories deserve the tokens they occupy, and deleting the wrong memory silently degrades the agents that depended on it.

## The solution

`distributed-memory-optimization-suite` turns memory management into a deterministic, inspectable pass you can run on a schedule:

- **Retention scoring** — every entry gets a value score: `w.recency × 0.5^(age / halfLife) + w.frequency × log2(1 + accessCount) + w.importance × importance`. Recency halves on a configurable half-life, so a week-old untouched note fades while a repeatedly-touched one survives.
- **Similarity-based compaction** — near-duplicate entries are clustered (Jaccard similarity over token sets) and merged into a single **summary** entry that carries `sources` provenance back to everything it replaced, at a configurable compression ratio.
- **Budget eviction** — nodes over budget evict lowest-score-first. Pinned entries are untouchable: never merged, never evicted.
- **Multi-node coordination** — one `MemoryCluster` owns all nodes, enforces one shared config, and reports per-node and total savings.
- **Determinism** — inject the clock and id factory and every score, merge, and eviction decision is reproducible. The demo transcript is byte-stable and asserted by a test.
- **Zero runtime dependencies** — the library, HTTP server, and CLI run on the Node standard library alone.
- **Persistence** — versioned, atomically written (tmp + rename) state files with corruption detection.

## How it works

```
MemoryCluster
 ├─ MemoryStore "alpha" (capacity: tokens)    one store per node
 │   └─ MemoryEntry[]                          episodic | fact | summary
 ├─ MemoryStore "beta"
 └─ optimizeAll()
      ├─ compactStore()    cluster similar entries → summary with sources[]
      ├─ evictToTarget()   lowest score first, pinned immune
      └─ ClusterReport     per-node + total deltas
```

An **entry** is a unit of agent memory: content, a token cost, an importance in `[0, 1]`, a kind (`episodic`, `fact`, `summary`), timestamps, an access counter, and optional tags. A **summary** is generated by compaction: its content is the highest-scoring members' text (capped by `summaryHeadChars`), its `sources` list the replaced ids, and its access stats roll up from the members.

### Config knobs (`OptimizerConfig`)

| Knob | Default | Meaning |
|---|---|---|
| `halfLifeMs` | `86_400_000` | Recency half-life; score contribution halves every half-life of age |
| `weights.recency` / `frequency` / `importance` | `1 / 0.5 / 1.5` | Score weights, all must be ≥ 0 |
| `similarityThreshold` | `0.45` | Jaccard similarity for cluster membership, in `(0, 1]` |
| `minClusterSize` | `2` | Smallest group that gets merged |
| `targetUtilization` | `0.6` | Evict down to this fraction of capacity |
| `summaryHeadChars` | `400` | Content budget for generated summaries |
| `compressionRatio` | `0.35` | Summary tokens = `ceil(member tokens × ratio)` |

## Getting started

**From GitHub (no npm release):**

```bash
npm install github:Retsumdk/distributed-memory-optimization-suite
```

Bun blocks git-dependency lifecycle scripts by default; after `bun add github:Retsumdk/distributed-memory-optimization-suite`, run `bun pm trust distributed-memory-optimization-suite` once so `prepare` builds `dist/`.

**From a clone:**

```bash
git clone https://github.com/Retsumdk/distributed-memory-optimization-suite.git
cd distributed-memory-optimization-suite
bun install
bun run typecheck && bun test && bun run build
```

Requires Node ≥ 20 (built and tested with Bun 1.2).

## Library example

```ts
import { MemoryCluster } from "distributed-memory-optimization-suite";

const cluster = new MemoryCluster();
cluster.addNode("alpha", 500);

cluster.add({ node: "alpha", content: "queue depth alert on worker-1", importance: 0.4 });
cluster.add({ node: "alpha", content: "queue depth alert on worker-2", importance: 0.4 });

const report = cluster.optimizeAll();
console.log(report.totals);
// { entriesBefore: 2, entriesAfter: 1, tokensBefore: 16, tokensAfter: 6,
//   tokensFreed: 10, clustersMerged: 1, summariesCreated: 1, evictedCount: 0,
//   evictedIds: [] }

const store = cluster.node("alpha");
const summary = store!.entries()[0]!;
console.log(summary.kind, summary.sources, summary.tokens);
// summary [ 'm1', 'm2' ] 6
```

(`m1`/`m2` are the default `crypto.randomUUID()` ids replaced here for brevity; with the default factory your ids differ but the counts are identical.)

## HTTP API

Start with `dmos serve --port 8642 --token <secret>`. When `--token` is set, every mutation requires `Authorization: Bearer <secret>` (constant-time comparison); reads stay open.

| Method | Path | Notes |
|---|---|---|
| GET | `/healthz` | liveness |
| GET | `/stats` | cluster stats (nodes, totals, utilization) |
| GET | `/nodes` | per-node stats |
| POST | `/nodes` | create node `{ id, capacityTokens }` |
| GET | `/entries?node=&kind=` | list entries with optional filters |
| POST | `/entries` | add entry `{ node, content, tokens?, kind?, importance?, pinned?, tags?, id?, agent? }` |
| POST | `/entries/:id/touch` | refresh recency + accessCount |
| POST | `/entries/:id/pin` | set pin `{ pinned: boolean }` (blocks merge + eviction) |
| DELETE | `/entries/:id` | remove entry |
| POST | `/optimize` | compact + evict every node, returns the report |

Errors are JSON: `{ error: "<CODE>", message }` with `VALIDATION` → 400, `NOT_FOUND` → 404, `CONFLICT` → 409, `UNAUTHORIZED` → 401. Bodies are capped at 1 MB.

## Semantics and limits

- **Scores are not ages.** Recency uses `lastAccessAt`, not `createdAt`: touching an entry resets its decay clock and bumps `accessCount`, which is how a pinned-by-usage pattern emerges without pins.
- **Compaction preserves the extremes.** Pinned entries are excluded from clustering; a group smaller than `minClusterSize` is left untouched. Summaries can be re-compacted with further entries in later passes.
- **Eviction is strict.** Only unpinned entries are eligible; if the target cannot be reached without evicting pinned entries, eviction stops (the node stays over target rather than losing protected state).
- **Determinism is opt-in.** Default clock is wall time and ids are UUIDs; pass `clock`/`idFactory` (as the demo does) for reproducible runs.
- **Similarity is lexical.** Jaccard over word sets — no embeddings, no network calls. It reliably catches near-duplicate reports; it will not catch paraphrases with disjoint vocabulary.
- **State files are validated on load.** A wrong version, malformed node, or bad entry kind is a `CORRUPTION` error, never a silent partial restore.

## Project layout

```
src/
  types.ts        entry/config/report types + config validation
  errors.ts       MemoryError hierarchy (codes → HTTP status)
  scoring.ts      recency decay, frequency factor, entry score
  similarity.ts   tokenizer, Jaccard, text similarity
  store.ts        per-node MemoryStore (add/touch/remove/pin/stats)
  compactor.ts    greedy similarity clustering + summary generation
  evictor.ts      budget enforcement, lowest-score-first
  optimizer.ts    compact + evict per node
  cluster.ts      multi-node coordination, optimizeAll(), stats
  persistence.ts  atomic versioned state files
  server.ts       zero-dep HTTP API with bearer auth
  cli.ts          parseArgs CLI (demo/add/node/list/stats/optimize/serve)
  demo.ts         deterministic end-to-end demo
tests/            20 tests across 6 suites (72 assertions)
```
